# OMX 알약 자동 조제 — 트러블슈팅

각 항목은 **현상 → 원인 분석 → 조치 → 검증 → 재발 방지** 순으로 정리했습니다.
수치는 모두 실측값입니다.

## 문서 이용 안내

| 분류 | 내용 | 항목 |
|---|---|---|
| A | 학습이 의도와 다른 규칙을 학습한 사례 | A-1 ~ A-8 |
| B | 측정 방법의 오류 | B-1 ~ B-7 |
| C | 데이터 품질 사고 | C-1 ~ C-6 |
| D | 하드웨어 | D-1 ~ D-4 |
| E | 소프트웨어 · 조작 | E-1 ~ E-6 |

ACT 를 두 가지 방식으로 적용했으며, 문제가 발생한 지점이 다릅니다
(방식 설명은 [[OMX-조제-사용-기술]] §4 참조).

| 항목 | 해당 방식 |
|---|---|
| A-1 위치 암기 | 양쪽 공통 — 데이터 수집 단계의 문제입니다 |
| A-2 장면 암기 | **B (원-핫 단일 정책) 전용** |
| A-3 CVAE 우회 경로 | **B 전용** |
| A-4 색상 증강 | 양쪽 공통 |
| A-5 정지 조건 상실 | 양쪽 공통 |
| A-6 학습 장기화 시 악화 | **B 전용** |
| A-7 주입 강도 가설 기각 | **B 전용** |
| A-8 목표 표현 변경 실패 (좌표·표식) | **B 전용** |

> 방식 A(색별 정책)에는 목표 조건화 문제가 구조적으로 발생하지 않습니다.
> 각 정책이 자기 색만 학습하므로 지시를 무시할 방법이 없습니다.

# A. 학습이 의도와 다른 규칙을 학습한 사례

본 프로젝트에서 가장 많은 시간을 소모한 문제 유형입니다. **모델은 의도된 단서가 아니라
학습 손실을 가장 쉽게 낮출 수 있는 단서를 학습합니다.** 하나의 경로를 차단하면
다음으로 쉬운 경로를 탐색합니다.


## A-1. 배치 편중으로 인한 위치 암기

**현상**

파일럿 단계에서 노랑 알약 60개를 수집했습니다. 학습 손실은 0.086까지 정상적으로
감소했으나, 실기에서 알약 위치가 바뀌면 성능이 급격히 저하되었습니다.

**원인 분석**

파지 시점의 팔 각도(pan) 분포를 측정한 결과, 60개 에피소드가 세 개의 군집으로
뭉쳐 있었습니다.

```
파지 위치 표준편차     5.9
5도 구간 커버율        12칸 중 5칸
알약 배치 범위         화면 상단 40% 영역에 집중
```

"적당히 무작위로" 배치했다고 판단했으나 실제로는 편중되어 있었습니다. 모델은 화면에서
알약을 탐색한 것이 아니라 **대략적인 위치를 암기**한 상태였습니다. 학습 데이터에서는
이 규칙이 항상 성립하므로 손실이 낮게 유지되었습니다.

**조치**

1. 배치표를 난수로 생성하여 격자 전체(5×4 = 20칸, 8방향 각도)에 균등 분포시켰습니다.
2. 배치 영역을 `area.json` 으로 고정하고 매 에피소드 배치표대로 배치했습니다.
3. 화면 하단의 미사용 영역을 줄여 유효 해상도를 확보했습니다.

**검증**

| 지표 | 파일럿 | v2 |
|---|---|---|
| 파지 위치 표준편차 | 5.9 | **11.3** |
| 5도 구간 커버 | 5 / 12 | **8 / 12** |
| 최종 학습 손실 | 0.086 | 0.071 |

**재발 방지**

수집 완료 후 파지 위치 분포를 반드시 측정합니다. 손실 값만으로는 편중을 판단할 수 없습니다.

## A-2. 장면 암기로 인한 목표 무시 (방식 B)

**현상**

3색 데이터 96개를 수집하고 원-핫 목표 조건화를 적용했으나, "빨강을 집어라"는 지시에
대해 임의의 알약을 집었습니다.

```
자기색 대비 1.00     (틀린 목표를 입력해도 예측이 동일합니다)
```

증강 ON/OFF, 스텝 40K~128K, 에폭 2.8~9.0, 언어 지시(SmolVLA)까지 **모든 조건에서 1.00**
이었습니다.

**원인 분석**

기존 데이터는 각 배치가 **한 번, 한 목표로만** 등장하는 구조였습니다.

```
배치 A → 빨강 집기
배치 B → 초록 집기
배치 C → 노랑 집기
```

이 구조에서는 "해당 사진 = 해당 궤적"을 암기하는 것만으로 모든 학습 데이터가
설명됩니다. 목표를 참조할 유인이 존재하지 않습니다.

추가로, 목표는 인코더 토큰 603개 중 1개(0.17%)에 불과하여 무시해도 손실 증가가
미미합니다.

> **이 두 번째 요인은 이후 기각되었습니다.** 목표를 전 계층에 주입하는
> Diffusion Policy 에서도 개선되지 않았습니다(A-7 참조). 주입 면적은 부차적
> 요인이며, 주된 원인은 위의 데이터 구조입니다.

> Geirhos et al.(*Nature Machine Intelligence*, 2020)이 정리한 **지름길 학습**과
> 구조가 동일합니다. 해당 논문에서는 별/달 분류 과제에서 별이 항상 특정 위치에
> 있었기 때문에 모델이 모양이 아닌 **위치로** 분류했습니다.

**실기 증거**

동일 배치에서 원-핫만 변경하여 3회 실행한 결과, **3회 모두 노랑을 집었습니다.**

**조치**

두 가지를 병행했습니다.

*① 주입 방식 변경 — FiLM 도입*

목표가 닿는 면적을 토큰 1개에서 시각 특징 512채널 전체로 확대했습니다.

```
f' = (1 + γ(goal)) · f + β(goal)
```

*② 데이터 구조 변경 — 동일 장면 × 3목표 촬영*

동일 배치에 세 목표를 부여하여 장면만으로는 정답이 결정되지 않도록 했습니다.

```
32세트 × 3색 = 96개 + 정지 시연 32개 = 128 에피소드 (촬영 소요 약 3시간)
세트 내에서는 집은 알약을 동일한 칸 · 동일한 각도로 복원합니다
```

**검증**

![촬영 품질 — 위치 편차 분포](images/chart_drift.png)

촬영 품질을 먼저 검증했습니다. 동일 세트 3장에서 같은 알약의 위치 편차는
**중앙값 3.1mm**, 93.8%가 10mm 이내였습니다(격자 한 칸 42×33mm). 설계 의도대로
수집되었음을 확인했습니다.

조건화 지표는 A-3 으로 이어집니다.

**재발 방지**

목표 조건화 데이터를 설계할 때는 **"장면만으로 정답이 결정되는가"** 를 먼저 확인합니다.
결정된다면 목표 입력은 학습되지 않습니다.

## A-3. CVAE 잠재변수를 통한 목표 우회 (방식 B)

**현상**

A-2 의 조치를 적용한 후에도 자기색 대비가 80K · 90K · 100K 스텝에서 연속으로
**1.22 ~ 1.23** 에 정체했습니다. 암기가 불가능한 신규 세트만으로 측정해도 **1.20**
이었습니다.

한편 학습 손실은 **0.067까지 정상적으로 감소**했습니다.

![학습 진행에 따른 자기색 대비](images/chart_curve.png)

**원인 분석**

동일 장면에 정답이 셋인 데이터에서 손실이 이 수준까지 감소했다는 것은,
목표를 참조하지 않고도 정답을 알 수 있는 경로가 존재함을 의미합니다.

ACT 의 CVAE 인코더 구현을 확인한 결과 원인이 확인되었습니다.

```python
# modeling_act.py:417
if self.config.use_vae and ACTION in batch and self.training:
    action_embed = self.vae_encoder_action_input_proj(batch[ACTION])  # 정답 행동을 입력받습니다
    latent_sample = mu + sigma * randn()      # 학습: 정답에서 도출한 32차원 잠재변수
else:
    latent_sample = torch.zeros(...)          # 추론: 0
```

CVAE 인코더는 학습 시 **정답 행동 시퀀스 전체를 입력으로 받습니다.**

```
동일 장면, 목표 빨강  →  빨강으로 향하는 행동  →  잠재변수 z₁
동일 장면, 목표 초록  →  초록으로 향하는 행동  →  잠재변수 z₂
동일 장면, 목표 노랑  →  노랑으로 향하는 행동  →  잠재변수 z₃
```

세 경우의 z 가 서로 다르므로 디코더는 **z 만으로 목표를 식별할 수 있습니다.**
원-핫을 참조할 필요가 없습니다. 추론 시에는 `z = 0` 이므로 목표 정보가 소실되며,
FiLM 에 의한 약한 변조만 남습니다.

> **학습 손실이 낮게 나온 것 자체가 진단 근거였습니다.** 동일 장면에 정답이 셋인
> 데이터에서 손실이 그만큼 감소했다면, 목표 외의 경로에서 정답을 얻고 있다는
> 의미입니다.

**조치**

```bash
--policy.use_vae=false
```

잠재변수를 제거하면 목표 입력 외에는 대상을 식별할 방법이 없습니다.

ACT 원 논문에서 CVAE 는 사람 시연의 다중모드성을 흡수하는 장치입니다. 그러나 본
과제에서는 **그 다중모드성이 곧 목표가 설명해야 할 대상**이므로, 흡수 대상이
아니었습니다.

**검증 — 가설은 기각되었습니다**

`use_vae=false` 로 224 에피소드를 80K 스텝까지 학습하여 동일 조건과 비교했습니다.

| 조건 | 스텝 | 에폭 | 자기색 대비 |
|---|---|---|---|
| CVAE 사용 (기준) | 80K | 2.6 | **1.23** |
| CVAE 제거 (`use_vae=false`) | 80K | 2.6 | **1.13** |

잠재변수를 제거하자 오히려 **낮아졌습니다.** 따라서 CVAE 우회는 정체의 주된
원인이 아닙니다. 구현상 우회 경로가 존재하는 것은 사실이나, 그것을 차단해도
정책은 여전히 목표를 참조하지 않았습니다. 즉 **우회 경로가 하나 더 있거나,
목표 신호 자체가 너무 약해 참조할 유인이 없는 것**입니다. 후자는 A-7 에서
Diffusion Policy 로 검증했으며, 역시 기각되었습니다.

> **가설이 코드 근거를 갖추었더라도 통제 실험 전에는 원인으로 확정하지 않습니다.**
> 본 건은 구현을 직접 확인해 도출한 가설이었으나 실측에서 기각되었습니다.

**재발 방지**

목표 조건화를 적용할 때는 **모델이 정답 정보를 다른 경로로 받고 있지 않은지**
아키텍처 수준에서 확인합니다. 특히 학습 시에만 활성화되는 경로(VAE 인코더,
teacher forcing 등)를 점검합니다.

## A-4. 색상 증강이 색 판별 신호를 훼손

**현상**

색 판별이 요구되는 과제에서 LeRobot 기본 이미지 증강을 그대로 사용했습니다.

**원인 분석**

기본 증강 구성에 색상(hue) 변조가 포함되어 있었습니다.

```
hue        (-0.05, 0.05)  =  ±18도 회전
saturation (0.5, 1.5)     =  채도가 최대 절반까지 감소
```

실제 알약의 색상값과 비교하면 영향이 명확합니다.

```
빨강 354도    노랑 50도    초록 134도

색 간 간격    빨강↔노랑 56도    노랑↔초록 84도
±18도 변조 시  두 색이 최대 36도까지 근접 — 56도 간격의 64%가 잠식됩니다
```

![색상 증강이 색 간격에 미치는 영향](images/chart_hue.png)

**색이 정답인 과제에서 색을 변조하는 것은 라벨에 잡음을 주입하는 것과 동일합니다.**

동일 구성에 포함된 affine 증강도 문제가 있었습니다.

```
translate 0.05  →  이미지를 최대 32px = 21mm 이동
정답 행동(action)은 함께 변환되지 않습니다
→ 동일한 행동에 ±21mm 어긋난 이미지를 대응시켜 학습하는 결과가 됩니다
→ 그리퍼 여유(5~10mm)의 2~4배에 해당하는 위치 잡음입니다
```

**조치**

밝기 · 대비 · 선명도는 유지하고 색상과 affine 만 비활성화했습니다. 채도 범위는
0.9~1.1로 축소했습니다.

```bash
# 개별 가중치는 CLI 로 변경할 수 없습니다 (unrecognized arguments).
# tfs 전체를 JSON 문자열로 전달해야 합니다.
--dataset.image_transforms.tfs='{"hue":{"weight":0.0,...},"affine":{"weight":0.0,...},...}'
```

**재발 방지**

증강 항목을 선택할 때 **해당 항목이 변조하는 속성이 과제의 정답 신호인지** 확인합니다.
프레임워크 기본값이 모든 과제에 적합하지는 않습니다.

## A-5. 회복 시연 추가로 인한 정지 조건 상실

**현상**

트레이에 빨강이 없는 상태에서 빨강 정책을 실행하자 **회복 동작을 무한 반복**했습니다.
색 판별 자체는 정상이었습니다 — 초록으로 이동하지는 않았습니다.

**원인 분석**

집기 실패 시 재시도하는 **회복 시연 7개**를 데이터에 추가한 것이 원인이었습니다.

```
학습 데이터 96개    모두 "목표가 트레이에 존재하는" 상태입니다
회복 시연 7개       "실패하면 재시도하라"를 학습시킵니다
──────────────────────────────────────────────
목표 부재 상황      정의된 적이 없는 상태 + 재시도 성향 → 무한 탐색
```

**대조 실험**

회복 시연이 포함되지 않은 `act_v3_red29` 는 담은 후 **정지**했습니다.
자기색 대비 또한 회복 시연 추가 시 5.45에서 3.85로 저하되었습니다.

> de Haan et al.(*NeurIPS*, 2019)의 **인과 혼동** 사례에 해당합니다.
> "정보를 추가하면 성능이 저하될 수 있다"는 주장과 일치하며, 본 사례에서
> 회복 능력과 정지 조건은 **상충 관계**였습니다.

**조치**

**정지 시연 32개**를 신규 촬영했습니다. 목표 색을 약통에 담아둔 상태에서 해당 색을
지정하고, 리더암을 홈 자세에서 **15초간 정지**시킵니다.

3가지 상황을 모두 포함했습니다.

| 유형 | 개수 | 장면 |
|---|---|---|
| 목표만 없음 | 21 | 목표 색만 약통에, 나머지 2색은 트레이에 있습니다 |
| 두 개 담김 | 3 | 2색 처방 완료 직후 상태입니다 |
| 빈 트레이 | 8 | 3색 처방 완료 직후 상태입니다 |

**검증**

실기 검증은 미완료입니다.

**재발 방지**

새 능력을 학습시킬 때 **기존 능력과 상충하지 않는지** 확인합니다. 상충하는 경우
양쪽 상황을 모두 데이터에 포함해야 합니다.

## A-6. 학습 장기화 시 목표 무시 심화 (방식 B)

**현상**

```
원-핫 토큰 방식    목표 변경 시 행동 변화량 Δ
   40K 스텝        0.05
  128K 스텝        0.02      (감소)
```

학습 손실은 0.057까지 계속 감소하는 동안 목표 참조도는 오히려 저하되었습니다.

![목표 반응량 Δ](images/chart_delta.png)

**원인 분석**

학습이 진행될수록 지름길 규칙이 강화됩니다. 손실 감소에 기여하는 주 경로가
장면 암기이므로, 학습량 증가가 해당 경로를 더욱 정교하게 만듭니다.

**시사점**

"학습이 부족하여 실패한 경우"와 "지름길을 학습하여 실패한 경우"는 학습량 증가에 대해
**반대로 반응합니다.** 학습을 늘렸을 때 지표가 악화되면 학습량 문제가 아닙니다.

## A-7. 주입 강도 가설의 기각 — Diffusion Policy (방식 B)

**현상**

A-2 에서 "목표가 인코더 토큰 603개 중 1개(0.17%)에 불과하다"는 점을 부수적 원인으로
지목했습니다. 이 가설이 옳다면 목표를 더 넓게 주입하는 아키텍처에서는 개선되어야
합니다.

**검증 설계**

Diffusion Policy 는 관측을 `global_cond` 로 압축하여 디노이징 U-Net 의 **모든 계층에**
조건으로 전달합니다. 목표가 토큰 하나에 갇히지 않습니다.

```python
# modeling_diffusion.py:183, 279
global_cond = torch.cat([...], dim=-1)     # 상태 · 영상 · 목표를 하나로 결합
# 이후 모든 디노이징 블록에 조건으로 주입됩니다
```

비교 조건을 맞추기 위해 **동일 데이터셋 · 동일 100K 스텝**으로 학습했습니다.

| 항목 | 값 |
|---|---|
| 학습 | 100,000 스텝 / 2.44 에폭 / 배치 6 / 11시간 42분 |
| 최종 손실 | 0.008 |
| 구성 | `n_obs_steps` 2, `horizon` 16, `n_action_steps` 8, DDPM 100 스텝 |

**결과 — 가설은 기각되었습니다**

| 스텝 | 자기색 대비 | 목표 변경 시 Δ |
|---|---|---|
| 40K | 1.00 | 1.05 |
| 80K | 0.97 | 0.70 |
| 100K | **0.97** | **0.69** |

전 구간에서 기준선(1.02) 이하입니다. 같은 100K 지점의 ACT 는 1.22 였습니다.

**Δ 가 학습과 함께 감소합니다**(1.05 → 0.69). A-6 에 기록한 원-핫 토큰 방식의
현상(40K 0.05 → 128K 0.02)과 동일합니다. **아키텍처를 바꾸어도 학습이 진행될수록
목표 참조도가 낮아지는 경향은 재현되었습니다.**

| 아키텍처 | 목표 변경 시 Δ | 자기색 대비 |
|---|---|---|
| ACT + FiLM (100K) | 0.51 | 1.22 |
| Diffusion Policy (100K) | **0.69** | **0.97** |

색별로는 노랑 0.96 · 빨강 0.95 · 초록 1.00 으로, **세 색 모두 1.00 이하**입니다.
틀린 목표를 입력했을 때가 근소하게 더 정확했습니다.

**주목할 점은 Δ 가 ACT 보다 크다는 것입니다.** 목표 원-핫만 바꿨을 때 출력 행동은
오히려 더 크게 변합니다. 즉 **목표 신호는 충분히 도달하고 있으며 출력도 그에 따라
변하지만, 그 변화의 방향이 대상 알약과 무관합니다.**

주입 경로를 토큰 1개에서 전 계층으로 확대해도 개선되지 않았으므로, 주입 강도는
정체의 원인이 아닙니다.

**측정 신뢰성 확인**

Diffusion 은 과거 관측 `n_obs_steps`(2) 개를 큐에 요구합니다. 최초 측정에서는 동일
프레임을 복제하여 큐를 채웠고 1.02 가 나왔습니다. 학습 분포와의 불일치를 배제하기
위해 실제 직전 프레임으로 재측정한 결과가 **0.97** 입니다. 측정을 교정하자 값이
오히려 낮아졌으므로 결론은 측정 아티팩트가 아닙니다.

**남은 원인**

목표 조건화 실패의 후보 원인 중 셋이 실측으로 기각되었습니다.

| 가설 | 검증 방법 | 결과 |
|---|---|---|
| 장면 암기 | 미학습 장면 측정 (B-2) | 1.33 → 1.03. 상승분은 암기였음 |
| CVAE 우회 | `use_vae=false` (A-3) | 1.23 → 1.13. 기각 |
| 주입 강도 부족 | Diffusion `global_cond` (본 항목) | Δ 0.69 인데 0.97. 기각 |
| **데이터 · 과제 구조** | 미검증 | **남음** |

**재발 방지**

가설을 세울 때 **그 가설이 틀렸다면 무엇이 관측되어야 하는지**를 함께 정의합니다.
본 건에서는 "주입을 넓히면 대비가 오른다"를 사전에 명시했기 때문에, Δ 는 커졌으나
대비는 오르지 않은 결과를 기각으로 판정할 수 있었습니다.

## A-8. 목표 표현을 바꾸어도 대상을 선택하지 못함 (방식 B, 최종)

**현상**

A-7 까지의 결론은 "주입 강도가 원인이 아니다" 였습니다. 남은 후보는 목표 표현
자체였습니다. 목표를 기호(원-핫)에서 **좌표**로, 다시 **화면 속 표식**으로 바꾸어
두 차례 검증했습니다.

**설계 근거**

원-핫은 모델이 "이 기호 = 화면 속 저 위치" 를 스스로 이어야 합니다. 목표를 출력과
같은 공간(좌표)에 두면 이을 것이 줄고, 화면 안에 직접 그리면 이을 것이 없어집니다.

| 방식 | 목표 전달 | 모델이 해야 할 일 |
|---|---|---|
| 원-핫 | `[1,0,0]` | 기호 ↔ 화면 위치를 스스로 연결 |
| 좌표 | `[0.62, 0.31]` | 좌표 ↔ 화면 위치를 연결 (같은 공간) |
| 표식 | 그 위치에 그려진 고리 | 연결 불필요 — 표식으로 가면 됨 |

좌표 라벨은 탑뷰 첫 프레임에서 HSV 로 목표 색을 검출해 만들었습니다. **재촬영은
필요하지 않았습니다.**

| 검출 품질 | 값 |
|---|---|
| 단일 검출률 | 97.9% (188 / 192) |
| 모호(같은 색 2개 이상) | **0%** |
| 라벨 ↔ 실제 파지 위치 상관 | u↔shoulder_pan **−0.976**, v↔shoulder_lift −0.840 |

**측정 지표를 바꾼 이유**

앞선 실험에 쓰던 *자기색 대비* 는 "틀린 목표를 주면 오차가 커지는가" 를 봅니다.
그런데 **오차가 커지는 것과 다른 알약을 고르는 것은 다릅니다.** 목표 쪽으로 조금만
끌려가도 오차는 크게 벌어집니다. 실제로 좌표 정책은 자기목표 대비 3.68 을 냈으나,
같은 체크포인트의 대상 선택률은 51% 였습니다.

그래서 실전 질문에 직접 답하는 지표를 새로 정의했습니다.

```
지정 알약 선택률 = 같은 장면에서 각 알약의 좌표를 차례로 주었을 때,
                   예측 자세가 지시한 알약에 더 가까웠던 비율
                   50% = 무작위
```

**결과 — 두 방식 모두 무작위 수준**

![지정 알약 선택률](images/chart_xy_pick.png)

| 방식 | 스텝 | 측정 대상 | 선택률 |
|---|---|---|---|
| 좌표 | 50K ~ 150K | 학습 장면 | 50 · 51 · 50 · 51% |
| 좌표 + 표식 | 10K ~ 30K | **미학습 장면** | 55 · 54 · 54% |
| — 무작위 | | | 50% |

표본 112회, 95% 신뢰구간 ±9%p 로 **무작위와 구분되지 않습니다.**

**원인 분석**

좌표 정책의 예측 분포가 원인을 보여줍니다.

```
예측이 알약 근처에 떨어진 비율      80%     ← 알약을 찾을 줄은 안다
목표를 바꿨을 때 따라간 비율        18%     ← 어느 알약인지는 화면이 정한다
학습에 없던 임의 좌표에 대한 기울기 0.29    ← 암기는 아니나 부분 반응에 그침
```

**정책은 화면에서 알약을 고른 뒤 목표 쪽으로 18% 만 밀립니다.** 두 알약의 간격이
정규화 좌표로 0.23 인데 0.042 만 움직이므로 중간선을 넘지 못합니다.

학습 데이터 구성이 이를 뒷받침합니다.

```
구 데이터   98개 (52%)   랜덤 배치, 장면당 목표 1개  → 화면만으로 정답 결정
신규        90개 (48%)   동일 장면 × 3목표          → 목표 없이는 정답 불가
```

절반의 데이터에서 목표를 참조할 이유가 없어, 모델이 두 경로를 절충한 결과로
해석됩니다. 다만 **표식 방식에서도 개선되지 않았으므로**(54%), 데이터 구성만으로
설명되지 않는 부분이 남아 있습니다.

**부수 발견 — 공간 정렬이 필요한 조건화와 affine 증강은 함께 쓸 수 없습니다**

표식 1차 실험은 무효 처리했습니다. 표식은 모델 내부에서 그려지는데, 그 앞단의
`affine` 증강이 이미지를 최대 32px(≈21mm) 이동시키고 있었습니다. 표식만 원래
좌표에 남아, 학습 내내 대상에서 벗어난 위치에 찍혔습니다.

```
고리 반지름 15px  vs  이동량 32px   →  표식이 대상을 완전히 벗어남
목표 변경 시 반응 1.81도 (필요량의 9%), 10K·30K 동일 → 표식을 무시하도록 학습됨
```

`affine` 가중치를 0 으로 두고 재학습했으나 결과는 같았습니다(54%). 버그는 실재했고
수정했으나, 그것이 실패의 원인은 아니었습니다. A-4 에 기록한 "affine 은 이미지를
옮기지만 정답은 함께 옮겨지지 않는다" 가 목표 조건화에도 동일하게 적용됩니다.

**결론**

목표 전달 방식 다섯 가지가 모두 같은 지점에서 실패했습니다.

| 방식 | 결과 |
|---|---|
| 원-핫 토큰 | 1.00 |
| 원-핫 + FiLM | 1.22 (미학습 장면 1.03) |
| Diffusion `global_cond` | 0.97 |
| 좌표 | 선택률 51% |
| 좌표 + 화면 속 표식 | 선택률 54% |

**목표를 어떤 형태로 주느냐의 문제가 아니었습니다.** 기호를 좌표로 바꾸고, 좌표를
화면 안에 그려 넣어 연결 과정을 없애도 결과가 같았습니다.

**재발 방지**

1. **지표가 실전 질문에 답하는지 먼저 확인합니다.** 자기색 대비는 원-핫 비교용
   지표였고, "대상을 선택하는가" 에는 답하지 못했습니다. 3.68 을 성공으로 읽은 것이
   그 결과입니다(B-6).
2. **공간 정렬이 필요한 조건화에는 위치 이동 증강을 끕니다.**
3. **조기 판정 지점을 미리 정합니다.** 좌표 실험은 150K 까지 돌린 뒤에야 평평한
   것을 확인했습니다. 표식 실험은 30K(약 3시간)에 판정 기준을 걸어 조기 종료했습니다.

## B-1. 재학습을 진단 수단으로 사용

**현상**

정책 실패 시마다 "데이터를 추가하고 재학습한다"를 3일간 반복했습니다. 1회 소요 시간은
약 8시간입니다.

**원인 분석**

가설 검증 수단으로 재학습을 사용했기 때문입니다. 재학습은 여러 변수가 동시에 바뀌므로
가설을 분리하지 못하며, 소요 시간이 길어 시행 횟수가 제한됩니다.

**조치**

`probe_policy.py` 를 작성하여 **체크포인트에서 직접 계측**하는 방식으로 전환했습니다.

- 카메라를 하나씩 차폐하여 어느 입력에 의존하는지 측정
- 이미지를 픽셀 단위로 이동시켜 응답 민감도 측정
- 목표만 교체하여 조건화 여부 측정

**검증**

재학습으로 검증하려던 가설 **2건이 모두 오류로 확인**되었습니다. 재학습을 진행했다면
8시간이 소요되었을 것입니다.

**재발 방지**

원인을 지목한 후에 재학습을 수행합니다. 재학습으로 원인을 탐색하지 않습니다.

## B-2. 학습 데이터 기준 측정값을 성능으로 해석

**현상**

FiLM 적용 후 자기색 대비가 1.00에서 **1.33**으로 상승한 것을 개선으로 판단하고
자료에 반영했습니다.

**원인 분석**

측정을 **학습에 사용한 에피소드**에서 수행했습니다. 동일 모델을 미학습 에피소드에서
재측정한 결과는 다음과 같습니다.

| 측정 대상 | 자기색 대비 | 올바른 목표 입력 시 오차 |
|---|---|---|
| 학습 사용 에피소드 | 1.33 | 0.70 ~ 0.81 |
| 미학습 에피소드 | **1.03** | 1.98 ~ 3.10 |

색상별 미학습 기준값은 노랑 1.23 / 빨강 **0.99** / 초록 **0.87** 이었습니다.
빨강과 초록은 1.0 미만으로, 틀린 목표를 입력했을 때 오히려 오차가 작았습니다.
우연 수준입니다.

**1.33의 대부분은 장면 암기에 기인한 값이었습니다.**

![학습 장면과 미학습 장면 비교](images/chart_memorization.png)

**조치**

**지각 없는 기준선**을 산출하여 모든 측정값의 하한을 정의했습니다.

```
화면을 참조하지 않고 "목표 색 → 해당 색의 평균 궤적"만 출력하는 예측기 = 1.02
```

이 기준선은 모델 없이 데이터에서 직접 계산됩니다. 측정값이 이 근처면 지각이
학습되지 않았다고 판단합니다.

**검증**

구 FiLM 의 미학습 기준 1.03은 기준선 1.02와 동일한 수준으로, 일반화된 조건화
학습량이 사실상 0이었음을 확인했습니다.

**재발 방지**

- 측정 결과를 보고할 때 **측정 대상이 학습 데이터인지 명시**합니다.
- 지표에는 반드시 기준선을 함께 제시합니다.

## B-6. 실전 질문에 답하지 못하는 지표를 성과로 해석

**현상**

좌표 조건화 정책의 *자기목표 대비* 가 학습과 함께 1.05 → 3.68 로 상승했습니다.
사전에 정한 성공 기준(3.0)을 넘었으므로 성공으로 보고했습니다.

같은 체크포인트의 **지정 알약 선택률은 51%(무작위)** 였습니다.

**원인 분석**

두 가지 오류가 겹쳤습니다.

*① 지표가 다른 질문에 답하고 있었습니다*

```
자기목표 대비   틀린 목표를 주면 오차가 커지는가
선택률          지정한 알약을 고르는가
```

목표 쪽으로 **18%만 끌려가도** 정답 자세와의 오차는 3.68배가 됩니다. 오차가
커지는 것과 대상을 바꾸는 것은 다른 사건입니다. 자기목표 대비는 원-핫 비교용으로
정의한 지표였고, 그대로 가져다 쓴 것이 잘못이었습니다.

*② 학습에 사용한 에피소드에서 측정했습니다*

188 에피소드를 전부 학습에 넣고 그 188 개에서 측정했습니다. B-2 에 이미 기록한
오류를 반복한 것입니다.

**조치**

1. **실전 질문에 직접 답하는 지표를 정의했습니다** — 같은 장면에서 각 알약의 좌표를
   차례로 주고, 예측이 지시한 알약에 더 가까웠는지 셉니다. 무작위 = 50%.
2. **평가용 장면을 분리했습니다** — 동일 장면 5세트(15 에피소드)를 학습에서 제외하고
   거기서만 측정했습니다.
3. **표본을 늘렸습니다** — 접근 구간의 여러 시점에서 재어 28회 → 112회로 늘렸습니다.
   28회에서는 95% 신뢰구간이 ±18%p 여서 50% 와 구분되지 않았습니다.

**재발 방지**

지표를 정의할 때 **"이 값이 높으면 실제로 무엇이 되는가"** 를 한 문장으로 쓸 수
있어야 합니다. 쓸 수 없으면 대리 지표입니다. 그리고 대리 지표는 성공 기준으로
쓰지 않습니다.

## B-7. 감시 스크립트가 오류를 삼켜 11시간을 낭비

**현상**

Diffusion 학습(11시간 42분) 동안 체크포인트 자동 측정이 걸려 있었으나, 학습이
끝난 뒤 결과 파일이 비어 있었습니다. 체크포인트 10개 분량의 측정이 전부 유실되어
사후에 하나씩 다시 측정해야 했습니다.

**원인 분석**

```bash
R=$(timeout 1200 python probe_policy.py ... 2>/dev/null)   # 오류를 버림
RATIO=$(echo "$R" | grep -oE "평균 비율 [0-9.]+" ...)
[ -z "$RATIO" ] && continue                                 # 값이 없으면 조용히 넘어감
```

측정 스크립트가 `AttributeError: 'DiffusionConfig' object has no attribute
'chunk_size'` 로 매번 즉시 종료되었습니다. ACT 는 `chunk_size`, Diffusion 은
`horizon` 을 씁니다. 오류를 `/dev/null` 로 버리고 값이 없으면 `continue` 했으므로
**10회 연속 실패가 로그에 한 줄도 남지 않았습니다.**

**조치**

```bash
timeout 2700 python -u probe_xy.py ... > "$LOG" 2>&1      # 출력을 통째로 남긴다
if [ -z "$RATE" ]; then
  say "  !! 측정 실패 (코드 $RC)"; tail -5 "$LOG"          # 실패를 보고하고
  printf "%s\t%s\tFAIL(rc=%s)\n" ... >> $OUT             # 표에도 남긴다
fi
```

**재발 방지**

무인 감시 스크립트에서 **실패는 침묵이 아니라 기록이어야 합니다.** `2>/dev/null` 과
"값이 없으면 건너뛰기" 의 조합은 장시간 무인 작업에서 가장 비싼 실수입니다.

## C-3. 화면 96px 이동 현상 (근본 원인 미확인)

## C-4. 이물질 유입으로 인한 목표-단서 상관

**현상**

한 세트의 3개 에피소드 중 2개에만 트레이 상단에 볼펜이 놓여 있었습니다.

지름길과 정확히 동일한 유형입니다.

**검출 방법**

에피소드별 **픽셀 중앙값 배경**을 생성하여(이동 중인 팔이 제거됩니다) 직전 세트와
차분했습니다. 트레이 상단 `(225, 0)` 위치에 29×17 크기의 영역이 2개 에피소드에서만
검출되었습니다.

**조치**

해당 2개를 제거하고 재촬영했습니다. 이후 224개 전수 검사에서 이물질은 검출되지
않았습니다.

**재발 방지**

촬영 전 작업 영역에서 불필요한 물체를 제거합니다. 수집 완료 후 중앙값 배경 차분으로
전수 검사합니다.

---

## C-5. 미리보기 도구의 카메라 점유로 인한 녹화 실패

**현상**

녹화 창은 정상적으로 표시되나 에피소드가 저장되지 않는 현상이 **3회 반복**되었습니다.

**원인 분석**

배치 확인용 `preview_grid.py` 가 실행 중인 상태에서 녹화를 시작하면, 카메라가 이미
점유되어 LeRobot 이 장치를 열지 못합니다. V4L2 장치는 동시 스트리밍이 불가능합니다.

**조치**

녹화 직전 `kill_preview()` 를 호출하여 미리보기를 자동 종료하도록 수정했습니다.

```bash
kill_preview() {
  if pgrep -f preview_grid.py > /dev/null 2>&1; then
    pkill -f preview_grid.py; sleep 2
  fi
}
```

**재발 방지**

사람의 주의에 의존하는 절차는 **자동화로 대체**합니다. 동일 실수가 3회 반복된 후
자동화했으며, 이후 재발하지 않았습니다.

---

## C-6. 중간 에피소드 삭제 시 데이터 손상

**현상**

에피소드 삭제 도구 실행 후 총 프레임 수가 244,088이어야 하나 **1,224,970**으로
산출되었습니다.

**원인 분석**

LeRobot 은 **하나의 parquet 파일에 여러 에피소드를 저장**합니다. 초기 96개의 경우
최대 20개가 한 파일에 포함되어 있었습니다.

작성한 도구는 "에피소드마다 해당 파일을 재작성"하는 방식이었으므로, 같은 파일을
여러 번 덮어쓰면서 데이터가 중복 기록되었습니다.

**조치**

1. 백업에서 복원했습니다(사전에 전체 백업을 확보해 두었습니다).
2. **파일 단위** 처리로 재작성했습니다. 각 파일을 한 번만 읽고, 삭제 대상 행을
   필터링한 뒤 한 번만 기록합니다.
3. 전역 인덱스는 `start[에피소드] + frame_index` 로 계산하여 파일 내 에피소드
   개수와 무관하게 정확하도록 했습니다.

**검증**

재작성 후 3단계로 검증했습니다.

| 검증 항목 | 결과 |
|---|---|
| 메타 무결성 (번호 연속, 프레임 구간 연속) | 정상 |
| data parquet (행 수, frame_index, index 범위) | 전 에피소드 정상 |
| `LeRobotDataset` 로드 | 정상 |

**재발 방지**

외부 라이브러리의 저장 포맷을 수정할 때는 **구조를 먼저 확인**하고, 작업 전 백업을
확보합니다.

## D-1. wrist 카메라 반복 단절

**현상**

`error -71` 이 초당 22회 발생하고 장치 번호가 계속 증가하다가 장치 목록에서
사라졌습니다. 30분간 12회 재등록되었습니다.

**원인 분석**

`device descriptor read/64, error -71` 은 드라이버가 개입하기 이전, USB 최초 협상
단계의 실패입니다. 소프트웨어로 해결할 수 없는 전기적 문제입니다.

포트를 변경해도 동일하게 발생하여 본체 측 문제가 아님을 확인했습니다.

**조치**

케이블을 교체했습니다.

**검증**

교체 후 6시간 38분 동안 재등록 7회로 감소했으며, 저장된 데이터의 손상은 0건이었습니다.

**참고 — 초기 단계의 별도 원인**

초기에는 USB 자동절전도 원인이었습니다. 절전이 활성화된 장치만 단절되었고 모터는
정상이었습니다.

```bash
echo on | sudo tee /sys/bus/usb/devices/*/power/control
```

## D-2. 카메라와 로봇의 USB 대역폭 경합

**현상**

**조치**

카메라를 본체 포트에 직접 연결하여 경로를 분리했습니다.

**검증**

30fps 로 복구되었습니다.

# E. 소프트웨어 · 조작

## E-1. 한글 입력 시 로봇 종료

**현상**

다른 창에서 한글을 입력했을 뿐인데 로봇 제어 프로세스가 종료되었습니다.

**원인 분석**

pynput 은 **물리 키**를 인식합니다. 한글 두벌식 자판에서 `ㅂ` 은 물리 `q` 키(종료),
`ㄴ` 은 `s` 키에 해당합니다. 전역 리스너가 활성화된 상태에서는 포커스와 무관하게
입력이 전달됩니다.

**조치**

`--local-keys` 옵션으로 전역 리스너를 비활성화했습니다.

## E-2. 파지 시 팔 정지로 인한 교착

**현상**

그리퍼가 닫히는 동안 팔을 정지시키자 시스템이 무한 대기 상태에 진입했습니다.

**원인 분석**

```
팔 정지 → 화면 변화 없음 → 그리퍼가 완료 신호를 받지 못함 → 정지 상태 유지
```

**조치**

`--no-freeze-on-grasp` 를 항상 지정합니다.

## E-3. 청크 경계에서의 궤적 불연속

**현상**

팔이 주기적으로 y축 방향으로 급격히 이동했습니다.

**원인 분석**

액션 청크(100스텝)의 경계에서 예측이 불연속적으로 전환되기 때문입니다.

**조치**

`--temporal-ensemble` 을 적용하여 겹치는 청크를 지수가중 평균했습니다.

**검증**

증상이 소멸하고 파지에 성공했습니다. **재학습 없이 추론 설정 변경만으로 해결한
첫 사례입니다.**

---

## E-4. 실기 검증 없는 계측값 적용

**현상**

시간 앙상블 계수를 계측값 `-0.05` 로 설정하자 팔이 하강하지 않았습니다.
보정식 적용 시에도 팔이 과도하게 움직였습니다.

**원인 분석**

- 앙상블 계수는 계측으로 산출했으나 실기 검증을 수행하지 않았습니다.
- 보정식은 파지 자세 범위(깊이 −9.8~63.9)에서 적합한 것을 홈 자세(116)에 적용하여
  외삽 오류가 발생했습니다.

**조치**

- 계수를 0.01로 복원했습니다.
- 보정은 접근 진행도를 곱하여 파지 근처에서만 적용되도록 변경했습니다.

**재발 방지**

**계측값도 실기 검증 전에는 적용하지 않습니다.**

## E-5. bash 연관배열 선언 누락

**현상**

촬영 스크립트 실행 즉시 `빨강: syntax error: operand expected` 로 종료되었습니다.

**원인 분석**

`declare -A` 없이 `EN[빨강]=red` 를 사용하면 bash 가 인덱스 배열로 생성하고
**한글 첨자를 산술식으로 해석**합니다.

**조치**

```bash
declare -A EN=( [빨강]=red [초록]=green [노랑]=yellow )
```

**검증**

첫 에피소드 촬영 전에 검출되어 데이터 오염은 발생하지 않았습니다.

## E-6. 코드 복원 후에도 잔존하는 저장 상태

**현상**

rerun 뷰어 레이아웃을 변경했다가 코드를 원복했으나 화면이 계속 변경된 상태로
표시되었습니다.

**원인 분석**

rerun 은 애플리케이션별 레이아웃을 로컬에 저장합니다. 코드를 원복해도 저장된
레이아웃이 우선 적용됩니다.

**조치**

```bash
rm ~/.local/share/rerun/blueprints/recording.rbl
```

**재발 방지**

코드를 원복해도 **저장된 상태(설정 파일, 캐시)** 가 남아 있으면 계속 적용됩니다.
원복 시 상태 파일도 함께 확인합니다.

# 종합 — 반복 확인된 원칙

**1. 모델은 의도된 단서가 아니라 가장 쉬운 단서를 학습합니다.**
하나의 경로를 차단할 때마다 "이제 무엇이 가장 쉬운가"를 다시 검토해야 합니다.
본 프로젝트에서 위치 암기 → 장면 암기 → CVAE 잠재변수 순으로 3회 발생했습니다.

**2. 낮은 학습 손실이 경고 신호일 수 있습니다.**
목표를 참조해야만 해결 가능한 과제에서 손실이 낮다면, 다른 경로로 정답을 얻고 있을
가능성을 검토해야 합니다.

**3. 학습 데이터 기준 측정값은 그대로 신뢰할 수 없습니다.**
동일 모델이 학습 데이터에서 1.33, 미학습 데이터에서 1.03을 기록했습니다.
기준선을 함께 제시하면 해석 오류를 방지할 수 있습니다.

**4. 재학습은 진단 수단이 아닙니다.**
체크포인트에서 직접 계측하고, 재학습은 원인을 지목한 후 1회만 수행합니다.

**5. 데이터 규모를 확대하기 전에 물리 세팅을 측정합니다.**
두 차례의 데이터셋 재구축이 모두 데이터 부족이 아니라 세팅 문제에 기인했습니다.
