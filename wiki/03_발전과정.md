# OMX 알약 자동 조제 — 개발 과정

**AI 기반 대학병원 환자 안내 및 약국 자동 조제 로봇 시스템** / OMX 조제 파트

여러 색이 섞인 트레이에서 **처방된 색만 순서대로 골라 약통에 담는** 로봇을
만드는 과정입니다. 시도한 순서가 아니라 **문제가 풀려 간 순서**로 정리했습니다.

| 단계 | 무엇을 풀었나 | 결과 |
|---|---|---|
| 1 | 알약 하나를 정확히 집기 | 위치 암기 → 배치 랜덤화로 해결 |
| 2 | 색을 구분해 원하는 것만 집기 | 색별 정책 3개로 해결 |
| 3 | 정책 하나로 세 색 처리하기 | 다섯 번 실패 → 좌표 조건화로 해결 |
| 4 | 여러 알약을 순서대로 조제하기 | 실행 구조 문제 4건 수정 후 해결 |
| 5 | 없는 약은 집으러 가지 않기 | 정지 시연 + 검출 확인으로 해결 |

---

## 1단계 — 알약 하나를 정확히 집기

### 문제: 손실은 낮은데 실기에서 못 집는다

노랑 60개로 시작했습니다. 학습 손실은 0.086까지 정상적으로 내려갔는데,
알약 위치가 바뀌면 성능이 급격히 떨어졌습니다.

### 진단: 화면을 보지 않고 위치를 외웠다

파지 시점의 팔 각도 분포를 재보니 60개가 세 군집으로 뭉쳐 있었습니다.

```
파지 위치 표준편차   5.9
5도 구간 커버율      12칸 중 5칸
알약 배치 범위       화면 상단 40% 에 집중
```

"적당히 무작위로" 놓았다고 생각했지만 실제로는 편중돼 있었습니다. 그 데이터에서는
**대략적인 위치를 외우는 것만으로 손실이 낮게 유지**됩니다.

> 손실 값만으로는 이 문제를 볼 수 없습니다. 데이터 분포를 직접 재야 합니다.

### 해결: 배치를 난수로 생성

격자 5×4 = 20칸과 8방향 각도를 난수로 조합한 배치표를 만들고, 배치 영역을
`area.json` 으로 고정했습니다.

| 지표 | 파일럿 | 개선 후 |
|---|---|---|
| 파지 위치 표준편차 | 5.9 | **11.3** |
| 5도 구간 커버 | 5 / 12 | **8 / 12** |
| 최종 손실 | 0.086 | 0.071 |

## 2단계 — 색을 구분해 원하는 것만 집기

### 접근: 색마다 정책을 따로 학습

각 정책이 자기 색만 학습하므로 "빨강을 집어라" 는 **빨강 정책을 불러오는 것**으로
표현됩니다. 목표 입력이 없으니 지시를 무시할 방법이 구조적으로 없습니다.

### 결과: 실기 동작 확인

데이터를 96 → 224 에피소드로 늘려 재학습했습니다. 학습 조건은 그대로 두고
**데이터만 2.4배**로 바꿔, 개선분이 무엇 덕인지 헷갈리지 않게 했습니다.

| 색 | 자기색 대비 | 자기색 오차 |
|---|---|---|
| 초록 | 3.72 → **4.77** (+28%) | 0.926 → **0.640** (−31%) |
| 노랑 | 3.96 → **4.61** (+16%) | 0.762 → **0.646** (−15%) |
| 빨강 | 2.79 → **3.00** (+8%) | 1.042 → **0.743** (−29%) |

### 배운 것: 마지막 체크포인트가 최선이 아니다

| 색 | 학습 경과 | 정점 |
|---|---|---|
| 초록 | 40K 4.24 → 87K 4.77 | 최종 |
| 노랑 | 60K 4.61 → 89K 3.81 | 6에폭 |
| 빨강 | 80K 2.60 → 90K 3.00 → 99.6K 2.53 | 9에폭 직전 |

그리고 **실기 순위가 오프라인 순위와 뒤집혔습니다.** 노랑은 오프라인 1위(60K,
4.61)가 실기에서 알약을 못 집었고, 오프라인 최하위(89K, 3.81)가 정상 동작했습니다.

> 체크포인트 선정은 오프라인 지표로 하지 않습니다.

## 3단계 — 정책 하나로 세 색 처리하기

색별 정책 3개는 동작하지만 색을 추가할 때마다 학습을 한 번 더 해야 합니다.
정책 하나가 `π(행동 | 관측, 목표)` 형태로 세 색을 모두 처리하는 것이 원래 설계였습니다.

### 다섯 번의 실패

목표를 **어떻게 전달할지**를 바꿔 가며 다섯 번 시도했습니다.

| 방식 | 목표 전달 | 자기색 대비 |
|---|---|---|
| 원-핫 토큰 | 인코더 토큰 1개 (603개 중) | 1.00 |
| 원-핫 + FiLM | 시각 특징 512채널 전체를 변조 | 1.22 (미학습 장면 1.03) |
| CVAE 제거 | 잠재변수 우회 경로 차단 | 1.13 |
| Diffusion Policy | `global_cond` 로 전 계층 주입 | 0.97 |
| SmolVLA | 언어 지시 | 1.02 |
| — 기준선 | 화면을 보지 않는 예측기 | **1.02** |

전부 기준선 근처였습니다. **목표를 어떤 형태로 주느냐의 문제가 아니었습니다.**

> **SmolVLA 는 원인이 달랐습니다** (2026-08-18 확인). `--policy.type=smolvla` 로만
> 시작해 `load_vlm_weights` 기본값 False 로 학습돼, 사전학습 가중치 없이 500M
> 시각-언어 모델을 백지에서 학습했습니다. `"red"` 와 `"green"` 이 다른 단어라는
> 것조차 모르는 상태였습니다. 나머지 다섯은 신호가 도달했는데 쓰지 않은 것이고,
> 이것은 신호 자체가 의미를 갖지 못한 것입니다.

### 가설을 하나씩 기각한 과정

```mermaid
flowchart LR
    S1["알약을 비슷한 자리에 배치"] --> P1["위치 암기"]
    P1 -->|"배치 랜덤화"| S2["각 장면이 한 목표로만 등장"]
    S2 --> P2["장면 암기"]
    P2 -->|"동일 장면 × 3목표"| S3["CVAE 가 정답을 입력으로 받음"]
    S3 --> P3["잠재변수로 목표 우회"]
    P3 -->|"use_vae=false"| R1["1.23 → 1.13<br/>기각"]
    R1 --> S4["목표 신호가 약한가"]
    S4 -->|"Diffusion 전 계층 주입"| R2["Δ 는 커졌으나 0.97<br/>기각"]
    R2 --> S5["목표가 기호라서인가"]
    S5 -->|"좌표로 변경"| R3["해결"]

    style P1 fill:#f8e5e3,stroke:#a8342d
    style P2 fill:#f8e5e3,stroke:#a8342d
    style P3 fill:#f8e5e3,stroke:#a8342d
    style R1 fill:#eceff3,stroke:#59636e
    style R2 fill:#eceff3,stroke:#59636e
    style R3 fill:#e2f2e9,stroke:#1f7a4d
```

각 가설은 **기각될 조건을 미리 정하고** 검증했습니다.

| 가설 | 검증 방법 | 결과 |
|---|---|---|
| 장면 암기 | 학습에 안 쓴 장면에서 측정 | 1.33 → 1.03 — 상승분은 암기였다 |
| CVAE 우회 | `use_vae=false` 통제 실험 | 1.23 → **1.13** 으로 악화 — 기각 |
| 주입 강도 부족 | Diffusion 으로 전 계층 주입 | Δ 0.51→0.69 인데 0.97 — 기각 |

세 번째가 중요합니다. Diffusion 은 **목표에 대한 반응이 ACT 보다 컸는데도**(Δ 0.69)
결과는 더 나빴습니다. 신호는 도달하는데 **그것이 무엇을 가리키는지** 배우지 못한
것입니다.

### 해결: 목표를 기호에서 좌표로

원-핫 `[0,1,0]` 은 모델이 "이 기호 = 화면 속 저 위치" 를 스스로 이어야 합니다.
그 연결을 배우는 것보다 장면을 외우는 쪽이 항상 손실이 빨리 떨어집니다.

**목표를 출력과 같은 공간에 두면** 그 연결이 필요 없습니다.

```
원-핫   [0,1,0]         목표 값이 3종류 — 224개를 찍어도 3종류
좌표    [0.62, 0.31]    목표 값이 188종류 — 랜덤 배치가 여기서 신호가 된다
```

색 판별은 학습이 아니라 **HSV 임계값**으로 처리합니다. 빨강 354°·노랑 50°·초록 134°
로 56도 이상 벌어져 있어 분류 문제가 아닙니다.

**라벨은 재촬영 없이 기존 데이터에서 만들었습니다.**

| 라벨 품질 | 값 |
|---|---|
| 단일 검출률 | 97.9% (188 / 192) |
| 모호(같은 색 2개 이상) | **0%** |
| 라벨 ↔ 실제 파지 위치 상관 | u↔pan **−0.976** / v↔lift −0.840 |

### 실기 결과

**좌표 조건화(`act_xy_224`)와 원-핫+FiLM(`act_film_224`) 모두 3색 연속 조제에
성공했습니다.** 4단계의 실행 구조 문제를 고친 뒤의 결과입니다.

## 4단계 — 여러 알약을 순서대로 조제하기

단독으로는 되는데 연속으로는 마지막 색이 실패했습니다. **원인은 정책이 아니라
실행 구조 네 가지**였고, 전부 실기 기록으로 특정했습니다.

### ① 성공 판정이 빈손을 성공으로 봤다

그리퍼가 닫혔다 열리기만 하면 성공으로 처리했습니다. 빈손으로 닫아도, 회복 중
재시도로 놓아도 같은 신호가 납니다.

**두 조건을 함께 봅니다** (224 에피소드 실측).

```
① 물었는가   관측 그리퍼 최솟값 ≥ 49.85
             성공 49.89~51.89 (알약 두께만큼 덜 닫힘) / 실패 49.04~50.13
② 약통인가   놓는 순간 shoulder_pan −28 ~ −21  (실측 −23.6~−25.5)
```

검증: 성공 192건 모두 검출, 실패 25건 오판 0건.

### ② 실패 판정이 로봇 명령을 버렸다

실패로 판정할 때 `continue` 를 썼는데, 그 아래에 `robot.send_action` 이 있었습니다.
**판정이 반복되는 동안 팔이 멈췄습니다.** 두 번째 색이 안 움직인 원인입니다.

### ③ 시간 앙상블이 ACT 이외의 정책을 마비시켰다

`--temporal-ensemble` 은 ACT 전용입니다. Diffusion·SmolVLA 에는 그 필드가 없어
값이 무시되는데, 함께 적용되는 `n_action_steps = 1` 만 남습니다.

```
50스텝 청크에서 첫 1스텝만 실행 → 팔이 제자리에 머문다
```

오프라인으로 확인하니 정책 자체는 정상이었습니다(예측 이동폭 6.80 vs 정답 6.30).

### ④ 좌표 정책이 로봇 팔을 목표로 잡았다

팔이 알약에 접근하면 알약을 가리고, 그때 검출기가 **로봇 본체의 빨간 부품**을
목표로 잡았습니다. 목표가 166px 아래로 튀고 팔이 그리로 따라갔습니다.

```
프레임  80~320   x 255  y 124   실제 알약 위치
프레임    400    x 274  y 290   로봇 쪽으로 튐
프레임  480~800  x 255  y 120   돌아옴
```

**팔이 낮을 때만 목표를 갱신**하도록 고쳤습니다(`shoulder_lift ≤ −35`).
지난 실행으로 검증하니 그 구간 250프레임에서 오검출 0건이었습니다.

빨강 접근 시간이 **39.1초 → 28.8초**로 줄었습니다 — 되돌아가던 구간이 사라진 만큼입니다.

## 5단계 — 없는 약은 집으러 가지 않기

### 왜 필요한가

과거 사탕 분류 프로젝트에서 색종이가 사라지자 정지 조건을 잃고 픽업을 무한
반복한 사례가 있었습니다. 조제 로봇에서는 **처방에 없는 약을 담는 사고**가 됩니다.

### 정지 시연 32개

목표 색을 **약통에 넣어 둔 채** 그 색을 지시하고 팔을 15초간 정지시켜 촬영했습니다
(색별 10~11개). 사람이 몰았을 때 **15초 동안 0.05도**만 움직였습니다.

### 문제: 학습은 됐는데 5초 만에 풀렸다

오프라인으로는 정지 시연 프레임에서 **14/14 정지**(평균 0.17도)로 완벽했습니다.
그런데 실기에서는 팔이 움직였습니다.

```
스텝   0~140   lift −60~−61   홈에서 정지 유지 (5초)
스텝 152       홈에서 3도 이탈
스텝 160~      −54.9 → −47.6  들리기 시작 → 집으러 감
```

정책은 홈에서도 **프레임마다 미세한 값**을 내고, 그것이 누적돼 5초 만에 홈을
벗어납니다. 한 번 들리면 그 자세는 정지 시연에 없어 판단이 풀립니다.

### 시간으로는 가를 수 없다

```
정상 집기가 홈을 떠나는 시각   중앙값 2.68초, 90% 3.98초
정지가 풀린 시각               5.1초
```

겹칩니다. 어떤 문턱을 잡아도 정상 집기의 28% 이상을 막았습니다.

### 해결: 트레이에 목표 색이 있는지 직접 본다

홈 근처에서만 HSV 로 확인하고, 없으면 홈 자세를 유지합니다.

| 검출 기준 | 값 | 근거 |
|---|---|---|
| 색 범위 | 빨강 H169~178 / 초록 H63~71 / 노랑 H26~29 | 실제 캡슐 화소의 10~90 분위 |
| 채도 | 노랑 S 46~82 | 하한을 80 으로 잡으면 노랑을 전부 놓친다 |
| 크기 | 15 ~ 1200 px | 캡슐은 절반만 유색이라 색 영역이 35~85px |
| 영역 | 트레이 안만 (x 91~415, y 102~305) | **약통은 트레이 밖 — 담긴 약은 후보가 아니다** |

검증: **정상 집기 0/48 막음, 정지 실패 0/32.** 양쪽 다 0%입니다.

> 이 장치는 정책의 능력이 아니라 **안전장치**입니다. 정책 성능을 평가할 때는
> `HOLD=0` 으로 끄고 봅니다.

## 방법론에서 배운 것

**① 손실은 진단에 쓸 수 없습니다.**
1단계에서 손실 0.086 인데 실기가 무너졌고, 3단계에서는 손실이 0.067까지
내려가는 동안 목표 추종이 1.22 에 머물렀습니다. 손실이 낮다는 것은
