# 발표 자료 — 핵심

10~15분 발표에 실제로 쓸 것만 모았습니다.
데이터를 어떻게 만들었는지는 `../03_준비과정/`, 근거 원본은 `../02_전체/` 에 있습니다.

## 한 줄 요약

여러 색이 섞인 트레이에서 **처방된 색만 순서대로 골라 약통에 담는** 로봇을
모방학습으로 만들었습니다. 목표 조건화에 다섯 번 실패하고 여섯 번째에
해결했습니다.

---

## 발표 순서와 근거

### ① 알약 하나를 정확히 집기 — 위치 암기를 잡다

손실은 0.086 까지 정상적으로 내려갔는데 알약 위치가 바뀌면 무너졌습니다.
**손실만으로는 이 문제가 보이지 않습니다.** 데이터 분포를 직접 쟀습니다.

```
목표 알약이 shoulder_pan 기준 세 덩어리에만 몰림   9 / 9 / 10개
덩어리 사이 4.7단위(약 8.5°)에는 데이터가 한 프레임도 없음
```

손으로 "대충 흩어놓기" 로는 무작위가 안 됩니다 — 사람은 트레이의 익숙한 칸으로
돌아갑니다. 그래서 **난수로 자리를 뽑아 놓고 그대로 놓았습니다.**

**`배치설계_오버레이.png`** — 뽑은 배치를 실제 카메라 화면에 겹친 것입니다.
번호와 화살표가 놓을 자리와 각도를 가리키고, 이 그림을 보면서 촬영했습니다.
`seed` 를 적어 두어 같은 표를 다시 뽑을 수 있습니다.

| 지표 | 파일럿 | 배치 설계 후 |
|---|---|---|
| 파지 위치 표준편차 | 5.9 | **11.3** |
| 5도 구간 커버 | 5 / 12 | **8 / 12** |

**이 프로젝트에서 성능을 가장 크게 움직인 것은 학습 설정이 아니라 촬영
설계였습니다.** 전체 배치표·오버레이·촬영 스크립트는 `../03_준비과정/` 에
있습니다.

> 근거: `../02_전체/문서/WORKLOG_20260805.md`, `../03_준비과정/배치설계/`

### ② 색을 구분해 원하는 것만 집기 — 색별 정책 3개

각 정책이 자기 색만 학습하므로 목표 입력이 없습니다. 지시를 무시할 방법이
구조적으로 없습니다. 데이터를 96 → 224 로 늘려 재학습했습니다.

| 색 | 자기색 대비 | 자기색 오차 |
|---|---|---|
| 초록 | 3.72 → **4.77** (+28%) | 0.926 → **0.640** (−31%) |
| 노랑 | 3.96 → **4.61** (+16%) | 0.762 → **0.646** (−15%) |
| 빨강 | 2.79 → **3.00** (+8%) | 1.042 → **0.743** (−29%) |

**`fig_checkpoints.png`** — 정점이 마지막 체크포인트가 아닙니다. 노랑은
오프라인 1위(60K)가 실기에서 알약을 못 집었고, 최하위(89K)가 정상 동작했습니다.

### ③ 정책 하나로 세 색 — 다섯 번의 실패

**`fig_goal_methods.png`** — 이 발표의 중심 그림입니다.

| 방식 | 목표 전달 | 자기색 대비 |
|---|---|---|
| 원-핫 토큰 | 인코더 토큰 1개 | 1.00 |
| 원-핫 + FiLM | 시각 특징 512채널 변조 | 1.22 |
| CVAE 제거 | 잠재변수 우회 차단 | 1.13 |
| Diffusion | 전 계층 주입 | 0.97 |
| SmolVLA | 언어 지시 | 1.02 |
| **기준선** | 화면을 보지 않는 예측기 | **1.02** |

전부 기준선 근처입니다. **목표를 어떤 형태로 주느냐의 문제가 아니었습니다.**

기각한 가설과 근거:

| 가설 | 검증 | 결과 |
|---|---|---|
| 장면 암기 | 학습에 안 쓴 장면에서 측정 | 1.33 → 1.03 — 상승분은 암기였다 |
| CVAE 우회 | `use_vae=false` 통제 실험 | 1.23 → **1.13** 악화 — 기각 |
| 주입 강도 부족 | Diffusion 전 계층 주입 | Δ 0.51→0.69 인데 0.97 — 기각 |

세 번째가 중요합니다. Diffusion 은 **목표 반응이 ACT 보다 컸는데도** 더
나빴습니다. 신호는 도달하는데 그것이 무엇을 가리키는지 배우지 못한 것입니다.

**`fig_onehot_ignores_goal.png`** — 목표를 바꿔도 예측이 겹칩니다.

### ④ 해결 — 목표를 기호에서 좌표로

```
원-핫   [0,1,0]         목표 값이 3종류 — 224개를 찍어도 3종류
좌표    [0.62, 0.31]    목표 값이 188종류 — 랜덤 배치가 여기서 신호가 된다
```

라벨은 **재촬영 없이** 기존 데이터에서 만들었습니다.

| 라벨 품질 | 값 |
|---|---|
| 단일 검출률 | 97.9% (188 / 192) |
| 모호(같은 색 2개 이상) | **0%** |
| 라벨 ↔ 실제 파지 위치 상관 | u↔pan **−0.976** |

**`발표_xy_좌표조건화.mp4`** (91초) — 3색 연속 조제.
화면의 분홍 원은 **녹화용 표시**이고 정책 입력이 아닙니다. 정책에는 숫자
두 개(u, v)만 들어갑니다. 영상 상단에 그렇게 적어 두었습니다.

### ⑤ 검출기 없이도 된다 — 원-핫 + FiLM

**`발표_원핫_film224.mp4`** (166초) — 검출기 없이 정책이 화면에서 색을 직접
찾아 3색을 담습니다. 「검출기가 다 한 것 아니냐」는 질문에 대한 답입니다.

| | 정책 | 3색 조제 시간 |
|---|---|---|
| 좌표 조건화 | 검출기 + 정책 | **91초** |
| 원-핫 + FiLM | 정책만 | 166초 |

좌표 쪽이 1.8배 빠릅니다 — 찾아 헤매는 단계가 없기 때문입니다.

### ⑥ 실행 구조 — 정책이 아니라 여기가 문제였다

단독으로는 되는데 연속으로는 마지막 색이 실패했습니다. 원인은 넷이고
전부 실기 기록으로 특정했습니다.

| 문제 | 조치 | 검증 |
|---|---|---|
| 성공 판정이 빈손을 성공으로 봄 | 그리퍼 최솟값 + 약통 위치 | 성공 192건 검출, 오판 0 |
| 실패 판정의 `continue` 가 로봇 명령을 건너뜀 | 분기 재작성 | 2번째 색 정지 해소 |
| 시간 앙상블이 ACT 외 정책을 마비 | ACT 전용으로 제한 | — |
| 좌표 정책이 로봇 팔을 목표로 잡음 | `lift ≤ −35` 일 때만 갱신 | 오검출 250프레임 중 0건 |

네 번째는 접근 시간이 **39.1초 → 28.8초**로 줄었습니다.

### ⑦ 없는 약은 집으러 가지 않는다

정지 시연 32개(색별 10~11개)로 학습했습니다. 사람이 몰았을 때 15초 동안
**0.05도**만 움직입니다.

실기에서는 5초 만에 풀렸습니다 — 정책이 홈에서도 미세한 값을 내고 그것이
누적돼 홈을 벗어나면, 그 자세는 정지 시연에 없어 판단이 풀립니다.

시간으로는 못 가릅니다(정상 집기가 홈을 떠나는 시각 중앙값 2.68초 vs
정지가 풀린 5.1초). **트레이에 목표 색이 있는지 직접 보는 것**으로 해결했습니다.

```
정상 집기를 막는 경우      0 / 48
정지를 못 시키는 경우      0 / 32
```

## 방법론 — 이 프로젝트에서 배운 것

**`fig_offline_vs_real.png`**

**① 손실은 진단에 쓸 수 없습니다.** 손실 0.086 인데 실기가 무너졌고,
0.067 까지 내려가는 동안 목표 추종은 1.22 에 머물렀습니다.

**② 오프라인 지표가 실기와 어긋난 사례가 네 건입니다.**
목표 조건화(1.22 → 성공), 좌표 선택률(51% → 성공), 노랑 체크포인트(1위 →
실패), Diffusion(정상 → 마비). 오프라인은 프레임 하나로 청크를 한 번
예측하는 **열린 루프**이고, 실기는 매 스텝 다시 예측하며 시각 되먹임으로
누적되는 **닫힌 루프**입니다.

**③ 지표가 실전 질문에 답하는지 먼저 확인합니다.** 같은 체크포인트에서
"자기색 대비 3.68" 과 "지정 알약 선택률 51%" 가 나왔습니다.

**④ 평가용 장면을 분리합니다.** 학습에 쓴 장면의 1.33 이 미학습 장면에서
1.03 이었습니다.

**⑤ 조기 판정 지점을 미리 정합니다.** 좌표 실험은 150K 까지 돌린 뒤에야
정체를 확인했고, 표식 실험은 30K 에 기준을 걸어 조기 종료했습니다.

## 예상 질문과 답

**「좌표를 주면 모방학습이라 할 수 있나」**

좌표가 대신하는 것은 **"세 개 중 어느 것"** 이라는 지목 하나뿐입니다. 접근
궤적·깊이 조절·파지 시점·운반·놓는 타이밍은 전부 시연에서 배웁니다. 그리고
좌표는 2차원(화면 u, v)인데 로봇은 3차원이라 깊이와 손목 각도는 이미지에서
학습해야 합니다.

무엇보다 **검출기 없는 판(`film224`)도 실기에서 3색이 됩니다.** 그 자리에서
돌려 보일 수 있습니다.

**「왜 SmolVLA 는 실패했나」**

`--policy.type=smolvla` 로만 시작해 `load_vlm_weights` 기본값 False 로
학습됐습니다. 구조만 가져오고 **가중치는 무작위**였습니다. SmolVLM2-500M 을
백지에서 학습시킨 셈이라 `"red"` 와 `"green"` 이 다른 단어라는 것조차 모르는
상태였습니다. 지시를 바꿔도 0.3~1.0도(필요량 20도의 2~5%)만 움직였습니다.

공식 문서는 `--policy.path=lerobot/smolvla_base` 를 쓰라고 합니다. 그 차이를
못 봤습니다.

**「알약 색을 더 늘릴 수 있나」**

| 방식 | 4번째 색 추가 |
|---|---|
| 좌표 xy | **HSV 범위 한 줄** — 재학습 없음 |
| SmolVLA | 새 색 시연 몇 개 + 이어서 학습 |
| 원-핫 FiLM | 벡터 차원 변경 → 처음부터 재학습 |
