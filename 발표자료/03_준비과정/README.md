# 준비 과정 — 데이터를 어떻게 만들었나

결과(`../01_핵심/`)를 만들어 낸 **설계와 노동**입니다. 모델을 고르기 전에
데이터를 어떻게 찍을지부터 설계했고, 그 설계가 이 프로젝트에서 가장 크게
성능을 바꿨습니다.

---

## 왜 배치를 설계했나

파일럿 30개는 손으로 "대충 흩어놓고" 찍었습니다. 결과는 이랬습니다.

```
목표 알약이 shoulder_pan 기준 세 덩어리에만 몰림   9 / 9 / 10개
덩어리 사이 4.7단위(약 8.5°)에는 데이터가 한 프레임도 없음
```

**손으로 무작위를 만들 수 없습니다.** 사람은 트레이의 익숙한 칸으로 돌아갑니다.
그 데이터로 학습하면 모델이 배우는 것은 "위치를 찾기"가 아니라 **"외운 세 개
접근 자세 중 고르기"** 입니다. 손실은 0.086 까지 정상적으로 내려가는데 실기가
무너지는 이유가 이것입니다.

그래서 **자리를 미리 뽑아 놓고 그대로 놓았습니다.**

| 지표 | 파일럿 | 배치 설계 후 |
|---|---|---|
| 파지 위치 표준편차 | 5.9 | **11.3** |
| 5도 구간 커버 | 5 / 12 | **8 / 12** |

## `배치설계/` — 난수로 뽑고 화면에 겹쳐 확인

### 만드는 쪽

| 파일 | 하는 일 |
|---|---|
| `plan_positions.py` | 격자 5×4 = 20칸과 8방향 각도를 난수로 조합해 배치표 생성 |
| `make_midpick_sheet.py` | 조제 중간 상태(약통에 이미 담긴 색이 있는 상황) 배치표 |
| `layouts.json` · `SETTINGS.json` | 배치 영역과 생성 설정 |

### 나온 것

**`*_배치표.md`** — 에피소드별 지시서입니다. `seed` 를 적어 두어 **같은 표를
다시 뽑을 수 있습니다**.

```
seed 3960
배치 영역 {'x0': 91, 'y0': 102, 'x1': 415, 'y1': 305}
각도 = 색깔 있는 끝이 향하는 방향 (0=오른쪽, 90=위, 반시계)

| ep | 목표 | 좌우% | 전후% | 각도 | 트레이에 함께 | 약통에 미리 |
|  0 | 빨강 |   46  |   32  | 242° | 초록 84/42 73° | 노랑        |
```

구성별 개수까지 설계했습니다 — 목표 하나만 3개, 초록과 함께 10개, 초록+노랑
5개, 노랑과 함께 2개. **한 줄이 곧 처방 중간 상태 하나**입니다.

**`*_오버레이.png`** — 뽑은 배치를 실제 카메라 화면에 겹친 것입니다.
번호와 화살표가 놓을 자리와 각도를 가리킵니다. 촬영할 때 이 그림을 보면서
알약을 놓았습니다.

**`*_시트.png`** · **`BATCH_SHEET.pdf`** — 인쇄해서 손에 들고 쓰는 판입니다.

## `촬영계획/` — 무엇을 왜 찍을지

| 파일 | 무엇을 찍는가 | 왜 |
|---|---|---|
| `record_sets.sh` | **같은 장면 × 3목표** 32세트 + 정지 32개 | 화면만 봐선 못 풀게 만든다 |
| `record_late.sh` | 약통에 이미 담긴 상태에서 집기 | 3색 조제의 2·3번째 차례 상황 |
| `record_stop2.sh` | 담은 뒤 정지 | 담고 나서 남은 알약을 계속 집는 문제 |
| `record_demo.sh` | 시연용 촬영 | 발표 영상 |
| `RECORDING.md` | 촬영 절차 전체 | 카메라·조명·초점 확인 순서 |
| `placements*.md` | 색별·목적별 배치 지시 | 촬영 중 참조 |
| `BATCH_TABLE.md` | 전체 촬영 배치 종합 | — |

**`record_sets.sh` 가 가장 중요합니다.** 같은 배치를 그대로 두고 목표만 바꿔
세 번 찍는 방식입니다. 이것 때문에 **224개 중 174개(78%)가 같은 장면에 다른
목표**로 존재하고, 그래서 정책이 "화면만 보고 답을 맞히는" 지름길을 쓸 수
없습니다.

목표 조건화가 다섯 번 실패했을 때 **첫 번째로 의심한 것이 이 지점**이었고,
확인해 보니 파일럿 데이터에는 같은 장면이 한 목표로만 등장했습니다.
그래서 다시 찍었습니다.

## 이 폴더가 보여주는 것

```
① 손으로 무작위를 만들 수 없다는 것을 데이터로 확인했다
②    → 난수로 배치를 뽑고 화면에 겹쳐 확인하는 도구를 만들었다
③    → seed 를 남겨 재현 가능하게 했다
④ 목표 조건화가 실패하자 데이터 구조부터 의심했다
⑤    → 같은 장면 × 3목표로 다시 찍었다 (78%)
⑥ 정지·회복 같은 예외 동작도 따로 설계해 찍었다
```

**모델을 바꾸기 전에 데이터를 바꿨습니다.** 이 프로젝트에서 성능을 가장 크게
움직인 것은 학습 설정이 아니라 촬영 설계였습니다.
