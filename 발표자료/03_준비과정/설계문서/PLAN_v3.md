# v3 설계 — 처음부터 다시 (2026-08-03 밤 작성)

빨강 20개로 다시 시작한다. 목표는 **성공하는 정책이 아니라 파이프라인 검증**이다.
20개로 성능이 나오지 않는다는 건 v2 에서 이미 확인했다 — 이번 20개는
"세팅이 세션 내내 안 흔들리는가"를 확인하는 데 쓴다.

## 왜 다시 하는가 (v2 에서 실제로 측정된 것들)

| 무엇이 | 어떻게 어긋났나 | 어떻게 알았나 |
|---|---|---|
| top 화각 기준 | 기준 파일이 **녹화 전** 저장본이라 실제 학습 화각과 6.4/3.2px 차이 | 녹화 20개 전수 측정 → ep2 에서 옮겨진 뒤 ep19 까지 고정 |
| top 카메라 | 세션 중 밀림 | 구역별 템플릿 매칭 |
| 매트·약통 | 매트 아래 11mm, 약통 6mm 밀림 (팔이 밀어올림) | `align_scene.py` |
| **wrist 초점** | **선명도 184 (학습 1287~5369) — 15배 흐림** | 정지 상태 30장 라플라시안 분산 |
| 홈 자세 | v1 파일럿 값을 쓰고 있었음 (wrist_roll 2.7도 차이) | 데이터셋 시작 자세 중앙값과 대조 |
| 정책 명령 | 깊이축 **66도/프레임** (학습 최대 0.64) | `run_policy.py --trace` |

**이 중 다섯 개가 물리 세팅 문제였다.** 데이터를 60개로 늘려도 그대로 남았을 것들이다.
그래서 데이터를 늘리기 전에 세팅을 먼저 못 박는다.

## 1. 하드웨어 — 흔들릴 수 있는 것을 없앤다

- [ ] **top 카메라를 벽에 고정** (붐암 폐기). 붐암은 건드릴 때마다 밀렸고,
      매트를 만질 때도 같이 흔들렸다
- [ ] **매트를 책상에 고정** — 양면테이프나 벨크로. 팔이 알약을 집을 때 매트를 밀어올린 게
      측정으로 확인됐다 (11mm)
- [ ] **약통 고정** — 같은 이유 (6mm 밀림)
- [ ] **wrist 렌즈 초점 링을 고정** — 맞춘 뒤 테이프나 락타이트. 진동에 풀린다.
      오늘 15배 흐려진 채로 평가 2회를 돌렸다
- [ ] 팔로워 케이블 경로 정리 — 매트 하단(x275~351)을 침범해서 `align_scene` 의
      매트 아래 패치를 오염시킨다. 케이블을 치우면 그 패치도 쓸 수 있다

고정한 뒤 **`preflight.py --save-ref` 로 기준을 다시 저장한다.** 단, 이번에는
**녹화가 끝난 뒤 학습 화각으로 기준을 다시 만든다**(아래 3번). v2 의 6px 사고가 그거였다.

## 2. 세션 시작 점검 (녹화·평가 전 매번)

`record.sh` / `run.sh` 가 자동으로 부르게 한다. 하나라도 실패하면 시작하지 않는다.

- [ ] **top 구역별 화각** — 로봇·매트 좌우·약통을 **따로** 잰다.
      중앙값(`align_top.py`)만 보면 카메라가 멀쩡한데 매트만 밀린 경우를 놓친다.
      실제로 오늘 놓쳤다. → `align_scene.py` 의 판정을 `preflight.py` 에 넣을 것
- [ ] **wrist 초점** — 라플라시안 분산이 학습 범위(1287~5369) 안인지.
      → `focus_wrist.py` 의 측정을 `preflight.py` 에 넣을 것
- [ ] 버스 통신 — `bus_check.py` 30초 감시 (끊김 0)
- [ ] 카메라 노출·밝기 — 매트 픽셀 평균이 기준과 ±5 안쪽

## 3. 녹화

- [ ] 데이터셋 **`1unasy/pill_v3`** 새로 시작. 카메라를 옮기므로 v2 와 섞을 수 없다
- [ ] **빨강 20개.** 배치표는 `plan_positions.py`, 새 seed
- [ ] 배치는 **오버레이 이미지를 보고** 놓는다 (`--overlay`). v2 에서는 종이 표를 보고
      눈대중으로 놓아 계획 대비 중앙값 18mm 어긋났다. 학습에는 큰 문제가 아니지만
      평가에서 같은 자리를 재현하려면 오버레이가 필요하다
- [ ] **깊이(전후) 커버리지를 우선한다.** v2 에서 실패는 깊이축에 몰렸다.
      좌우는 pan 하나로 결정돼 쉽고, 깊이는 lift·elbow 조합이라 어렵다
- [ ] 녹화 직후 **에피소드별 화각을 전수 측정**해서 중간에 밀렸는지 확인한다
      → `check_recording.py` 신규 (v2 때 임시 스크립트로 했던 것을 도구로 만든다)

## 4. 학습 후 기준 재생성 — **이번 사고의 핵심 교훈**

- [ ] 녹화가 끝나면 **학습 영상에서 화각 기준을 다시 뽑는다**
      (`preflight_ref/top_train.png` = 에피소드 시작 프레임 중앙값).
      녹화 전에 저장한 기준은 실제 학습 화각과 다를 수 있다 — v2 에서 6.4px 달랐다
- [ ] wrist 기준도 같이 만든다 (`wrist_train.png`) + **학습 때 선명도 범위를 기록**해둔다.
      그 범위가 있어야 나중에 초점이 풀린 걸 알 수 있다
- [ ] **홈 자세를 데이터셋에서 다시 계산**한다 (`home_pose.json` = 시작 자세 중앙값).
      v2 에서 v1 값을 쓰고 있었다

## 5. 학습

- [ ] ACT 30K, 이미지 증강 ON, 배치 8 (v2 와 동일 설정 — 3.4 step/s, 약 2.5시간)
- [ ] 원-핫 없음 (빨강 전용). 색 조건화는 3색을 다 모은 뒤에
- [ ] 학습 중 절전 억제: `systemd-inhibit --what=handle-lid-switch:sleep:idle`

## 6. 평가

- [ ] 평가 **전과 후** 모두 2번 점검을 돌린다. 세션 중 어긋났는지 알아야 한다.
      v2 에서는 사후 점검이 없어서 "언제부터 이상해졌는지"를 몇 시간 만에야 알았다
- [ ] `--trace` 를 항상 켠다. 명령이 튀는지(정책) 팔이 튀는지(서보)를 눈으로는 못 가른다
- [ ] 실패는 **유형 + 방향 + 거리**를 적는다. v2 의 진단은 성공률이 아니라
      "위쪽으로 빗나간다"는 방향 한 마디에서 풀렸다
- [ ] 배치표대로 15회, 같은 조건으로 끝까지. 중간에 설정을 바꾸면 그 판은 버린다
