# 프로젝트 컨텍스트 — OMX 알약 조제 모방학습

이 파일은 프로젝트 배경 설명용입니다. 작업을 시작하기 전에 반드시 읽고 아래 원칙을 따르세요.

## 담당자 및 역할
- 종수(사용자) 담당: OMX 로봇팔을 이용한 알약 pick&place 모방학습
- 팀 프로젝트명: AI 기반 대학병원 환자 안내 및 약국 자동 조제 로봇 시스템
- 다른 팀원들이 Pinky 자율주행, 웹 대시보드, 3D 매핑 등을 맡고 있고, 이 프로젝트는 그중 OMX(약국 조제) 파트만 다룸

## 하드웨어 / 환경
- OS: Ubuntu 24.04.4 LTS
- GPU: NVIDIA GeForce RTX 4060 노트북 (VRAM 8GB) — 애초 RTX 5080으로 알려졌으나 실제 확인 결과 4060임, 배치 사이즈를 작게 잡고 mixed precision 필수
- 가상환경: `~/venv/il` (활성화: `source ~/venv/il/bin/activate`)
- LeRobot 설치 위치: `~/il_ws/src/lerobot` (editable 설치, 버전 v0.4.4로 고정 — 최신(0.6.0)으로 업그레이드하지 않기로 결정함)
- 작업 폴더: `~/omx_pill_project`
- 로봇: OMX 팔로워 + 리더 암 (dynamixel-sdk 사용)
- 카메라 2대: 고정 오버헤드 카메라(`top`) + 그리퍼 상단 장착 카메라(`wrist`) — 그리퍼가 잡는 순간이 카메라에 명확히 보이는 것 확인됨

## 핵심 설계 원칙 (반드시 지킬 것)

1. **알약 4종을 항상 하나의 트레이에 섞어서 배치**한다. 종류별로 트레이를 따로 두지 않는다.
2. 모델은 **"목표로 지정된 알약 하나만 정확히 집기"**만 학습한다 (goal-conditioned policy). 여러 알약을 순서대로 옮기는 처방 로직(예: 감기=A+C+D)은 모델이 아니라 State Machine이 pick()을 반복 호출해서 처리한다 — 이 부분은 모델 설계에 포함하지 않는다.
3. 목표 지정 방식:
   - ACT / Diffusion Policy: 4차원 원-핫 벡터 (예: 빨강=`[1,0,0,0]`)
   - SmolVLA: 언어 텍스트 그대로 사용 (예: `"pick red pill"`)
4. 평가 기준: 지정된 알약을 정확히 집어야 성공. 다른 알약을 집으면 무조건 실패로 엄격하게 판정.
5. 데이터 수집 시 매 에피소드마다 **알약 위치·각도를 랜덤화**해야 함 (위치 고정 시 모델이 위치를 외워버리는 문제 발생). 목적지 위치도 몇 cm씩 자연스럽게 흔들 것.
6. 목표별 녹화는 몰아서 찍어도 무방함 (예: 빨강 60개 연속 → 파랑 60개 연속 ...). 학습 시 어차피 전체가 섞여서 사용되므로 녹화 세션 순서 자체는 성능에 영향 없음. (이 부분에 대해 긴 논쟁이 있었으나 최종적으로 "몰아서 찍기"가 맞는 방식으로 확정됨)
7. 가능하면 그리퍼 상태(비었음/찼음) 등 내부 상태 신호도 입력에 포함시킬 것 — 표면적 시각 단서(색 등)에만 의존해 오작동하는 causal confusion 문제를 예방하기 위함 (과거 사탕 분류 프로젝트에서 유사 실패 경험 있음: 색종이가 사라지자 정지 조건을 잃고 픽업 동작을 반복 시도한 사례).

## 기법 비교 계획 (난이도 순)
BC(직접 구현 베이스라인) → ACT → Diffusion Policy → SmolVLA(언어 조건화 파인튜닝)
- 필요시 VQ-BeT도 여유 있으면 추가 (필수 아님)
- v0.4.4 CLI 확인 결과 ACT, Diffusion 계열(VQ-BeT 포함 추정), WallX, X-VLA, SAC 등 다양한 `--policy.type` 지원 확인됨

## 메인 스토리 (강사 피드백 반영)
"이미 증명된 걸 재현하는 것"보다 **"실패 → 진단 → 개선"의 반복 사이클**을 보여주는 것이 프로젝트의 핵심 목표. 통계적으로 완벽한 통제 실험(에피소드 수/리더 속도/학습 스텝 정밀 비교)은 로봇 평가 시간이 지나치게 많이 필요해 부차적 항목으로 격하함.

## 4주 계획 요약
- 1주차: 환경 세팅 + 데이터 240개 수집(4종×60개) + BC 베이스라인
- 2주차: ACT 학습 → 실패 분석 → 개선 → 재검증 (사이클 1회차)
- 3주차: Diffusion Policy, SmolVLA 학습 및 비교 + 개선 사이클 2회차
- 4주차: 인과혼동 체크, 세트 완성률, 강건성 테스트, 포트폴리오 정리

## LeRobot v0.4.4 관련 확인된 사항
- `lerobot-record`, `lerobot-train` 등 최신 문서와 유사한 CLI 체계 사용 (완전히 동일하지 않을 수 있으니 매번 `--help`로 확인)
- 카메라 설정은 `--robot.cameras` 딕셔너리 형태로 `top`, `wrist` 키 사용 권장
- `--policy.image_key` 기본값이 `observation.images.top`이므로 카메라 이름을 `top`으로 맞추는 것이 기본 설정과 자연스럽게 호환됨
- HF Hub 자동 업로드는 기본값이 아니므로, 필요시 `--policy.push_to_hub=true` 명시적으로 켜야 함
