왜 원-핫 변환이 따로 필요한가

ACT 안에는 토크나이저도 언어 인코더도 없다. "pick red pill"이라는 문자열을 읽지 못한다. 목표를 받을 수 있는 통로는 observation.environment_state 하나뿐인데, lerobot-record는 이 항목을 만들지 못한다. 그래서 녹화가 끝난 뒤 task_index를 보고 원-핫 벡터를 계산해 새 피처로 붙인다.

키 이름이 정확히 observation.environment_state여야 FeatureType.ENV로 잡힌다. 다른 이름을 쓰면 STATE로 분류돼 관절값과 섞인다. ENV는 정규화 매핑에 없어 IDENTITY로 처리되므로 0/1이 그대로 들어간다.

정책 아키텍처

ACT는 ResNet18로 두 카메라를 인코딩한다. 480×640 입력이 15×20 특징맵이 되므로 카메라당 300 토큰, 두 대면 600 토큰이다. 여기에 latent · state · env_state가 하나씩 붙어 전체 603 토큰이 된다.

이미지600전체의 99.5%
목표(env_state)1전체의 0.17%
나머지2latent · state

이 비율이 첫 번째 원인이다. 목표가 토큰 하나로 들어가면, 어텐션이 그것을 무시하고 이미지 600개만 봐도 학습 손실은 충분히 낮아진다.

FiLM 목표 조건화 (로컬 패치)

토큰 하나 대신 모든 시각 채널을 목표로 변조하도록 바꿨다. FiLM(Feature-wise Linear Modulation)은 목표 벡터로 스케일 γ와 시프트 β를 만들어 512개 채널 전부에 곱하고 더한다. 

f' = (1 + γ(goal)) · f + β(goal)
# configuration_act.py
film_conditioning: bool = False        # 기본 꺼짐 — 기존 체크포인트 호환

# modeling_act.py — γ는 1 근처, β는 0 근처에서 출발하도록 마지막 층 0 초기화
self.film = nn.Sequential(
    nn.Linear(env_state_dim, dim_model), nn.ReLU(),
    nn.Linear(dim_model, 2 * dim_model),
)
nn.init.zeros_(self.film[-1].weight)
nn.init.zeros_(self.film[-1].bias)

# forward — 이미지 특징에 적용
gb = self.film(batch[OBS_ENV_STATE])
gamma, beta = gb.chunk(2, dim=-1)
cam_features = (1.0 + gamma[:, :, None, None]) * cam_features + beta[:, :, None, None]

env_state 토큰은 그대로 둔다. 없애면 위치 임베딩이 602 vs 603으로 어긋나 터진다. FiLM은 추가 경로로 넣는다. 원본은 *.orig로 백업돼 있다.

3. 평가 지표

재학습 없이 체크포인트에서 직접 재는 개입형 지표

자기색 대비

같은 관측에 목표만 바꿔 넣고 행동 예측이 얼마나 나빠지는지 잰다. 

자기색 대비 = (틀린 목표를 줬을 때의 오차) ÷ (올바른 목표를 줬을 때의 오차)

1.00  목표를 완전히 무시  (틀린 목표를 줘도 예측이 같다)
3.00  목표를 확실히 읽음

Δ — 목표를 바꿨을 때의 행동 변화량

원-핫 토큰 0.02 → FiLM 0.63. 31배. 주입 방식이 실제로 신호를 통과시킨다는 직접 증거다.

화면 기여도

정책 예측과 실제 목표 위치의 상관에서, 관절값만으로 설명되는 몫을 뺀 것.

계측 함정 — 상태 누출

파지 직전에서 재면 관절값만으로 상관 1.00이 나온다. 팔이 이미 알약 위에 있으니 당연하다. 파지까지 30% 지점에서 재야 화면 기여가 분리된다 (정책 0.77 vs 관절 0.01). 표본이 적으면 없는 신호가 보인다 — 6개로 보이던 순서 효과가 87개로 늘리니 사라졌다.

왜 에폭을 맞췄나

스텝만 맞추면 3색 정책은 색별 정책보다 데이터를 3배 적게 본다. 그러면 "목표를 무시해서 실패한 것"과 "덜 봐서 실패한 것"이 구분되지 않는다. 에폭을 맞춰야 데이터 노출량이 같아지고, 남은 차이가 목표 주입 방식 때문이라고 말할 수 있다.

더 오래 돌리면 오히려 나빠진다

원-핫 토큰의 Δ는 40K에서 0.05, 128K에서 0.02로 줄었다. 학습이 길어질수록 "장면만 외우는" 지름길이 깊어진다. 학습량 부족이 아니라는 반증이다.

정정 — 발표에서 뺀 결론

"증강이 색 구분을 만들었다"는 주장은 통제 비교를 통과하지 못했다. 10K 같은 조건(맨바닥 · 배치 8 · 같은 데이터, 증강만 다름)에서 증강 ON 1.30배 / OFF 1.62배로 오히려 OFF가 높았다. 기존 결론은 파인튜닝→맨바닥, 10K→40K, 증강 OFF→ON이 동시에 바뀐 실행들을 비교한 것이었다.

  • 화각이 세션 중 밀렸다 — 7/31에 발견. 붐암에 달린 카메라가 건드릴 때마다 움직였다
  • 배치가 쏠렸다 — 파지 시점 pan 표준편차 5.9, 5도 구간 8개 중 5개, 60개가 세 덩어리로 뭉쳤다. 위치를 외울 수 있는 구조
  • 화면의 아래 절반이 빈 바닥 — 알약이 위쪽 40%에만 놓여 해상도를 낭비했다
  • wrist USB 케이블이 녹화 중 빠졌다
그래서 바꾼 것

환경을 전부 재설계했다 — 트레이·화각·목적지. 세 번째 색으로 초록을 넣고, 목적지는 약통 1칸 고정으로 못 박았다. 환경이 달라졌으니 기존 60개는 섞을 수 없다. 지우지 않고 v1_pilot/에 남겨뒀다.

v2 — 20개 리허설이 물리 문제 5가지를 잡아냈다

본 수집 전에 20개만 찍어 세팅을 검증하는 단계를 넣었다. "20개로 성능이 나오나"가 아니라 "세팅이 세션 내내 안 흔들리나"를 보는 판이다. 이 판단이 옳았다 — 20개로 다음이 전부 측정됐다.

v3 — 흔들릴 수 있는 것을 먼저 없앤다

v3는 데이터를 늘리기 전에 하드웨어를 못 박는 것부터 했다.

  • top 카메라를 벽에 고정 — 붐암 폐기 (건드릴 때마다 밀렸다)
  • 매트와 약통을 책상에 고정 — 팔이 밀어올린 것이 11mm / 6mm로 측정됐다
  • wrist 렌즈 초점 링 고정 — 진동에 풀린다
  • 기준 화각을 녹화가 끝난 뒤 학습 화각으로 다시 저장 (v2의 6px 사고 재발 방지)
  • 팔로워 케이블 경로 정리 — 매트 하단을 침범해 정합 패치를 오염시켰다

같은 장면 × 3목표 — 왜 이렇게 찍었나

기존 데이터는 각 배치가 딱 한 번, 한 목표로만 등장했다. 그래서 "이 사진 = 이 궤적"으로 외워도 학습 데이터가 전부 맞는다. 목표를 읽을 이유가 없다. 같은 배치에 세 목표를 붙이면 장면만으로는 답이 셋이라, 목표를 읽어야만 손실이 준다.

개수 지름길을 확인하고 기각한 사례

새로 찍은 128개만 보면 집기는 전부 트레이 3개 상태에서 시작하고 정지는 전부 3개 미만이다. "3개면 집고 아니면 멈춰라"만 배우면 손실이 0이 되는 구조로 보였다. 그런데 예전 96개를 열어보니 1개·2개에서 집는 장면이 이미 많았다(48개 표본에서 1개 ~10 · 2개 ~22). 지름길은 존재하지 않았고, 추가 촬영 20개 제안은 철회했다.

우리 결과는 어디에 서 있나

저널 vs 학회

이 분야의 원전(ACT, BC-Z, CLIPort, Causal Confusion)은 대부분 CoRL·NeurIPS·RSS 등 학회 논문이다. 국제학술지 등재본만 고르면 원전이 빠지므로, 저널 3편을 주축으로 하고 학회 원전은 보조로 표기했다.

① 값싼 조건화 진단 지표

같은 관측에 목표만 바꿔 넣어 예측 변화를 재는 개입. 로봇도, 새 데이터도, 재학습도 필요 없다. 체크포인트만 있으면 몇 분이면 된다.

대부분의 논문은 최종 성공률만 보고한다. 성공률이 낮을 때 그것이 "조건화 실패"인지 "정밀도 부족"인지 구분해주지 않는다. 이 지표는 그 둘을 가른다. 실제로 우리 정책은 지각·위치잡기는 처음부터 됐고(화면 기여 +0.76) 조건화만 안 됐는데, 성공률만 봤다면 둘을 구분하지 못했을 것이다.

② 통제된 반증

조건을 하나씩 바꿔가며 전부 실패함을 보였다 — 증강 ON/OFF, 스텝 40K~128K, 에폭 2.8~9.0, 사전학습 언어모델(SmolVLA)까지. 에폭을 맞춘 것이 핵심이다.

③ 실기 영상 증거

report/fig_onehot_ignores_goal.png — 같은 배치에서 원-핫만 바꿨는데 세 번 다 노랑을 집었다. 숫자보다 전달력이 크다.

발표에서 쓸 한 문단

목표 조건화 실패는 Geirhos et al.(Nature Machine Intelligence, 2020)이 정리한 지름길 학습의 로봇 조작 판 사례로 볼 수 있다. 우리는 같은 관측에 목표만 바꿔 넣는 개입으로 이를 재학습 없이 정량화했고(자기색 대비 1.00배), 증강·스텝·에폭·사전학습 언어모델을 각각 통제해 전부 실패함을 보였다. 대규모 언어 조건화 연구(BC-Z 100과제, CLIPort 10과제)에서 이 문제가 드러나지 않는 것은 데이터 규모가 장면–목표 대응을 자연히 다양하게 만들기 때문으로 보이며, 소규모(96 에피소드) 환경에서는 데이터 구조를 명시적으로 설계해야 함을 시사한다.

정직하게 밝힐 것

원인 지목까지는 했으나, 고쳐서 증명하지는 아직 못했다. 같은 장면 × 3목표 128 에피소드를 새로 찍어 재학습을 돌리는 중이고, 자기색 대비가 1.33배를 유의하게 넘는지가 유일한 미검증 부분이다. 발표에 명시할 것.

10. 미해결과 다음

진행 중

train/act_film_224 — ACT + FiLM, 새 데이터 224개(245,529프레임), 증강 ON, 배치 8, 200,000 스텝 = 6.5 에폭 ≈ 16시간 30분, 1만 스텝마다 저장.

이번 학습의 변수는 데이터 구조 하나뿐이다. 주입 방식(FiLM)도 증강도 배치도 그대로다. 그래서 결과가 1.33배를 넘으면 "데이터 구조가 원인이었다"를 직접 증명한다. 지난번엔 40K에서 이미 실패가 보였으므로 40~60K쯤에서 판단이 선다.

미해결

  • prescribe.py가 안 움직인다 — GPU 0% / CPU 100%로 돌기만 한다. 카메라 가설은 기각됐고 원인 미상. 시연은 검증된 demo_chain.sh로 우회.
  • top 화면 +96px 밀림의 근본 원인 — 재현 조건은 찾았으나 lerobot의 어느 경로인지 미확인. 검출로 대응 중.
  • 초록 정밀도 — 초록으로 가긴 하는데 정확히 못 집는다. 흰 캡슐에 초록 끝이라 배경과 덜 구분되는 것으로 보인다(지표도 셋 중 가장 낮은 3.26배).
  • 오프라인 지표와 실기의 불일치 — 지표는 "학습 장면의 궤적 재현"을 재고 실기는 새 배치다. 지표는 방향, 판정은 실기.

이 프로젝트의 이야기

"이미 증명된 걸 재현하는 것"이 아니라 실패 → 진단 → 개선의 반복이 핵심이다. 목표 조건화 실패는 Geirhos(2020, Nature Machine Intelligence)의 지름길 학습이 로봇 목표 조건화에서 나타난 사례다. 대규모 연구는 데이터 규모가 이 문제를 우연히 가려주지만, 소규모에서는 그대로 드러난다. 기여는 세 가지 — 재학습 없는 개입형 진단 지표, 증강·스텝·에폭을 통제한 반증, 실기 영상 증거.
